State an app can read

### Added
- `mduct status --json` — the whole instance as one object: daemon, paths, and every server with `{transport, state, connected, note, auth}`. `mduct servers --json` is that server array on its own. Neither autostarts the daemon, so polling is safe.
- `auth.state` per server: `valid` · `refreshable` (lapsed, the daemon renews it on the next call) · `expired` · `unauthorized` · `n/a`. When a human has to act, `auth.fix` is the command to run — so a dashboard can show a dead login instead of you meeting it mid-task. Fields: https://github.com/TheFox666/mduct/wiki/Commands#machine-readable-state

### Changed
- A config that does not load is reported by `status --json` in an `error` field with exit 0, instead of only as a failure. `servers --json` still exits 1 there, because an empty array would claim no servers are configured.

### Fixed
- `mduct shadow` counted no conversions at all: the counter still matched the pre-rename binary name.
