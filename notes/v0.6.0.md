Codex hooks, and flags that parse

### Breaking
- Anything with a leading dash is now an option: `--foo=bar` no longer reaches the tool as an argument named `--foo`, and an unknown option fails the call. Pass tool arguments as `foo=bar`.

### Added
- `mduct hook install codex` registers the hooks and the catalogue in `~/.codex/config.toml`, between two markers. It refuses when `[hooks]` or `[mcp_servers.mduct]` already exist outside that block, rather than writing a file TOML would reject.
- `--version`. It printed the help and exited 1 before.
- `brew install thefox666/tap/mduct` tracks releases: the formula is generated from the published `.sha256` assets instead of by hand.

### Changed
- `-h`/`--help` exits 0. Asking for help is not an error.
- A `bash` shadow rule also matches Codex's `shell_command` and `exec_command` — the field matches a command line, not a tool name.

### Fixed
- `--timeout=5` was read as a tool argument, so the call went out with an extra field, without the timeout, and nothing on stderr.
- A mistyped `--jsonn` was reported as a bad argument, which pointed at the wrong fix.
- The `hook install` help line named Claude only, and `mduct shadow` still answered in German.
